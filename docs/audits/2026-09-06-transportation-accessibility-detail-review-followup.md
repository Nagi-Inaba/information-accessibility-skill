# フォローアップ: 未確認の理由表示とページ内リンクの検査

このメモは、[公開サイトの検査事例](2026-09-06-transportation-accessibility-detail-review.md)から得られた利用者の疑問を、スキル改善の検討材料として整理したものです。提供元は[PR #158](https://github.com/Nagi-Inaba/information-accessibility-skill/pull/158)、文書の修正日は2026-09-14です。修正時の実サイト再検査や、新たな利用者への聞き取りは行っていません。

改善したい点は、未確認の項目について「なぜ確認が残るのか」「次に何をすればよいか」が分かることと、ページ内リンクの利用上の問題を再現できる記録にすることです。

## 未確認42件から分かった表示上の課題

提供された元のレポートは55基準中42件を「未確認」とし、理由を一律に「この検査では確認していません。」と記載していました。提供者は、これだけでは検査できなかった理由が分からず、追加でエージェントに質問したと報告しています。この使用感を改善の出発点とします。

今回の検査は静的HTML解析だけでした。ただし、[E1](../../codex/skills/information-accessibility-practice/references/standards-assessment.md#4-grade-evidence-separately)は自動検査・静的解析・限定的な確認の証拠区分であり、「静的解析しか行えない」という制約ではありません。スキルには[ブラウザを使う検査経路](../web-inspection.md)もあります。42件が残った理由を、すべてスキルの原理的な限界と説明することはできません。

理由の表示では、少なくとも次の事情を区別できると役立ちます。これらは今後の表示案であり、当初の42件の原因内訳を確定したものではありません。

| 確認が残る事情 | この事例で次に行うこと |
| --- | --- |
| 必要な検査を今回実施していない | 拡大表示、キーボード操作、読み上げ位置等を実環境で確認する。検査不能だったのか、単に未実施だったのかも分ける。 |
| 該当コンテンツがない可能性がある | 元の記録では画像・動画・フォーム等がないとされる。基準ごとの適用条件を確認してから、人による結果として対象外の扱いを検討する。 |
| 内容や機能の意味を照合する必要がある | 見出し・リンク文言を対象の内容やリンク先と照合する。 |
| 今回の対象範囲だけでは足りない | ナビゲーションの一貫性等は、必要なページ群や一連の利用手順へ対象を広げて確認する。 |

検査の実施状況と、人による評価の完了は別の情報です。AIが観測を増やしても、人が確認していない機械可読profile行は`mapping_status: unverified`、`outcome: not_tested`のまま保持します。レポートだけの判定語から、人による検証済みの結果を作成してはいけません。

修正版レポートは55基準を個別に示し、追加で必要な確認を記載しました。適合とする根拠が足りなかった6件も要確認に変更したため、現在の集計は「適合4、要確認9、未確認42」です。これは文書上の判定根拠の修正であり、検査を追加実施した結果ではありません。

## 目次リンクで読み上げ位置が移動しないという報告

提供者の記録には、スクリーンリーダー利用者がページ内の目次リンクを起動しても、読み上げ位置が移動しないと報告したことが記されています。これは利用上の問題として残します。一方、ブラウザ・スクリーンリーダーの名前と版、操作モード、起動方法、対象ページの固定版は記載されておらず、原因は未確定です。

元のソース確認の記録では、`href="#common"`等とジャンプ先の`id`は対応し、ジャンプ先はsectionや見出し等で、`tabindex`は使われていなかったとされています。この属性の有無だけでは、読み上げ位置が移動しないことを確定できません。

ページのスクロール位置、DOMのフォーカス、次のTab移動の開始位置、スクリーンリーダーの読み上げ位置は、区別して記録する必要があります。[HTMLのフラグメント移動](https://html.spec.whatwg.org/multipage/browsing-the-web.html#scroll-to-fragid)にはフォーカス処理と次のフォーカス移動の開始位置を設定する手順があります。`tabindex="-1"`やJavaScriptの`.focus()`が常に必要だとは言えません。

`tabindex="-1"`の追加は検証する対策候補の一つです。最初に現状を再現し、次にローカルの検証用コピーで属性のみの変更を比較します。明示的な`.focus()`は、その対象環境で必要性が確認できた場合に検討します。ページ内リンクがあるだけで一律にJSを追加したり、規格違反と判定したりする検査にはしません。

### ページ内リンクの再現手順

1. 対象URLと版、OS、ブラウザと版、スクリーンリーダーと版、読み上げ・操作モードを記録する。
2. 目次の対象リンクとスキップリンクを分け、TabとEnterによる起動、および報告で用いた起動方法を確認する。
3. 起動後のスクロール、DOMフォーカス、次のTab移動先、読み上げ位置をそれぞれ記録する。読み上げ位置はスクリーンリーダーで確認し、DOMフォーカスだけから推定しない。
4. 必要な場合はローカルコピーでジャンプ先への`tabindex="-1"`追加を比較する。追加前後の読み上げと次のTab移動を確認する。
5. 明示的なフォーカス処理を追加する場合は、その必要性と効果を同じ環境で確認し、戻る操作や通常のページ内移動への影響も確認する。

この手順は今後の検査案です。実施結果はまだありません。対象サイトの変更は、この文書の修正には含みません。
