# 人手レビューのワークシート

登録済みの人手確認キューから、CSV・Markdown・Excel（XLSX）の入力用ワークシートを作成できます。確認者が判定と証拠を記入すると、取り込みCLIが `declared-human-review` の候補を生成します。JSONを手書きする必要はありません。

対象は現行のrun 11、queue 3です。runの状態が `human_queue_ready` または `human_review_recorded` の間に使用します。改善計画の登録後は新しいレビューを追加できません。ワークシートには対象URL、箇所、氏名、証拠の記述を含むため、非公開の作業資料として保管してください。

## 作成・記入・取り込み

次の例では、キュー `ART-REVIEW-QUEUE` が `run-queued.json` に登録され、成果物の保存先が `./artifacts` に設定されているものとします。`--queue` にはファイル名ではなく、登録済みキューのIDを指定します。

```sh
accessibility-audit human-review export --run ./run-queued.json --queue ART-REVIEW-QUEUE --format xlsx --output ./artifacts/review-sheet.xlsx
```

`--format csv` または `--format markdown` でも同じ項目を出力できます。CSVはUTF-8、Markdownは表形式です。XLSXには配布packageの依存ライブラリ `exceljs` 4.4.0が必要です。未導入の場合はスキルのディレクトリで `npm install --ignore-scripts` を実行してください。CSV・Markdownの操作ではこのライブラリを読み込みません。

入力区分が「入力」の行について、「値」列だけを編集します。基準名、対象箇所と必要な状態、手順、一次資料、必要な証拠の種類は固定欄です。行の追加・削除・並べ替え、項目キーや固定欄の変更は取り込み時に拒否します。Excelでは項目キー列を隠し、入力セルを淡い黄色にしています。文字と入力区分でも識別でき、色だけに依存しません。シート保護は編集補助であり、改変防止の保証や署名ではありません。

Excelで長文が隠れる場合は、行の高さを自動調整してください。行の高さの変更は取り込みに影響しません。固定欄も選択できるため、手順やURLはセルの内容から参照できます。

確認者の氏名、確認日、確認の申告を記入し、基準ごとに次の判定を選びます。

| 入力値 | 意味と記入内容 |
| --- | --- |
| `pass` | 適合。判定理由と、その基準が要求する種類の証拠を記入する。 |
| `fail` | 不適合。判定理由と証拠に加え、不適合の優先度（P0／P1／P2）、箇所、影響を受ける利用者、観測内容を記入する。指摘IDはCLIが生成する。 |
| `not_applicable` | 非該当。適用されない理由と、その判断に用いた証拠を記入する。 |
| `not_tested` | 未実施。`manual_observation` の欄に対象箇所、未実施の理由、記録日時を記入する。他の証拠欄は空欄にする。 |
| `cant_tell` | 判断不能。確認した範囲、判断できない理由、実際の証拠を記入する。 |
| 空欄 | 未提出。その基準の入力欄をすべて空欄にする。 |

証拠は種類ごとに、対象箇所・確認内容・記録日時を入力します。追加証拠の任意欄も2件あります。同じ種類の複数箇所は一つの欄に改行して列記できます。確認していない検査結果を記入してはいけません。必要な証拠を得られない場合、未実施として記録するか、その基準を未提出にして確認を続けます。

日時は `2026-09-19T10:30:00+09:00` のようにタイムゾーンを含む文字列で入力します。取り込み時にUTCへ変換し、秒未満の精度を保持します。存在しない日付や、取り込み時刻より未来の証拠日時は拒否します。確認日には実際の日付を `YYYY-MM-DD` で記入します。CSVをExcelで編集する場合も、文字コードをUTF-8、列の型を文字列として取り込んでください。

記入後、別名の新規ファイルへ取り込みます。

```sh
accessibility-audit human-review import --run ./run-queued.json --queue ART-REVIEW-QUEUE --input ./artifacts/review-sheet.xlsx --output ./artifacts/human-review.json --artifact-id ART-HUMAN-REVIEW
accessibility-audit register --run ./run-queued.json --artifact ./artifacts/human-review.json --output ./run-reviewed.json
```

`--artifact-id` は省略すると生成されます。入力形式は `.xlsx`／`.csv`／`.md` から判別し、必要なら `--format` で明示できます。出力先はrunに設定した非公開の成果物ディレクトリ内に限定します。既存ファイルは上書きしません。取り込みは候補作成までで、runを変更しません。登録時には通常の対象確認も行います。

## 一部提出・複数の確認者・再提出

1ファイルにつき確認者は1人です。一部の基準だけを提出できますが、判定が空欄なのに理由や証拠が記入されている場合は、入力漏れとして拒否します。未提出の基準は未評価のまま残ります。`not_tested` は「未実施を記録した」という提出であり、実施済みの評価件数には含めません。未実施だけの提出でE2へ上げることもありません。

複数の確認者が担当する場合は、担当基準を重複させず、それぞれ別ファイルを使用します。同じrunの状態で複数の候補を先に取り込んでから順次登録できます。1件登録した後に取り込む場合は、更新後のrunから新しいワークシートを出力してください。登録済みの基準は出力対象から除外されます。

固定欄にはrunのIDと正確なファイルhash、キューのIDとhashを保持します。runが更新された後の古いシート、別runのシート、改変されたキューに基づくシートは取り込めません。再出力したシートには、確認者が内容を再確認して回答欄だけを転記してください。

未登録の候補を修正する場合は、同じrunに対応するワークシートを修正し、別の出力名・artifact IDで取り込みます。不要な旧候補を登録しないようにしてください。登録済みレビューの差替えや、同じ基準に対する複数評価者の判定調停は未対応です。訂正が必要な場合は元の記録を保持し、新しいrunでレビューを行います。

## 検証範囲

取り込みでは、固定欄、同一run・キュー、手順と一次資料の対応、必要な証拠、不適合の必須情報を検証します。XLSXの数式・外部参照・マクロ・追加シート・結合セル、数値や日付型へ変換されたセルは受け付けません。入力は8MiB、ZIPは256項目、展開後は1項目8MiB・合計32MiB、表は12,000行を上限とします。

入力内容が実際の観測であることや、氏名を書いた人の本人性は、この処理だけでは証明できません。生成するレビューの `identity_authenticated` は常に `false` です。署名・本人性の検証が必要な場合は、登録後に[人手レビューの帰属と信頼方針](reviewer-assurance.md)の手順を使用してください。支援技術によるワークシートの実機操作は別途確認が必要です。
